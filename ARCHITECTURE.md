# Architecture

This document describes the repository as it is; it is updated with every
structural change.

**Owner:** personal (`github.com/kit-dix-pincott/terza-ui`)
**Type:** angular-ui-library
**Workspace:** nx (Nx 24, Angular 22, Node 26, pnpm 12)
**License:** MIT

## What this repository ships

- **`terza-ui`** on npm (unscoped), built from `libs/ui` with ng-packagr in
  the Angular Package Format. Published by the release workflow through npm
  trusted publishing.
- **The documentation site**, built from `apps/docs` and deployed to GitHub
  Pages by the release workflow. Its planned domain is `docs.terza.dev`; the
  custom domain is configured once its DNS exists.

## Layout

```text
libs/ui/                 ui        scope:ui        the published library (selector prefix tz)
  .storybook/                                      Storybook config and the axe test-runner hooks
apps/docs/               docs      scope:docs      the documentation site; imports the library from source
apps/docs-e2e/           docs-e2e  scope:docs-e2e  Playwright tests for the documentation site
  journeys/                                        journey inventory (the e2e coverage gate)
  fixtures/                                        house fixtures: checkedPage (axe), V8 coverage
  specs/                                           specs, tagged with journey ids
docs/                                              markdown documentation, the source of truth for AI docs
llms.txt                                           index of every docs/*.md file
tools/a11y/                                        reads the WCAG gate/target levels from the manifest
tools/scripts/                                     e2e flake log and merged coverage report
.repo/manifest.json                                machine-readable record of type, shape and toolchain
```

Component selectors use the `tz` prefix, enforced by ESLint in `libs/ui` and
`apps/docs`. Design tokens are CSS custom properties prefixed `--tz-`; none are
authored yet. Components are standalone and zoneless; the docs app runs
without zone.js.

## Boundaries

- Every project has a `scope` tag, and `@nx/enforce-module-boundaries`
  enforces the direction: `scope:ui` depends only on `scope:ui`; `scope:docs`
  may depend on `scope:ui`; `scope:docs-e2e` imports no workspace project (it
  tests the running site).
- The only shared code outside a project is `tools/a11y/conformance.ts`,
  imported by the e2e fixtures and the Storybook test-runner. It is the one
  explicit exception in the boundary rule.
- In development the docs app imports `terza-ui` from source (the
  `tsconfig.base.json` path mapping). The packaging gate builds it against the
  built package instead (`apps/docs/tsconfig.packaging.json` maps `terza-ui`
  to `dist/libs/ui`), so a packaging defect fails CI.
- The accessibility levels (gate AA, target AAA) live only in
  `.repo/manifest.json`; the e2e fixture and the Storybook runner derive their
  axe rule tags from it.
- AI-facing documentation is markdown in `docs/` indexed by `llms.txt`. An MCP
  server, if added, would be an additional package reading these files, not a
  restructure.

## Development infrastructure

- **Storybook** for `ui` (`storybook`, `build-storybook`, `static-storybook`
  targets). `test-storybook` is self-contained: it builds the static
  Storybook, serves it on port 6007, scans every story with axe at the gate
  level through `@storybook/test-runner` and `axe-playwright`, and stops the
  server.
- **Unit tests**: Vitest through the Angular unit-test builders, jsdom
  environment. Coverage thresholds (100% statements, branches and functions,
  per file) and the standing exclusions are set once in `nx.json`
  `targetDefaults`.
- **E2E**: Playwright via `@nx/playwright`. Projects: chromium,
  mobile-chromium, firefox, webkit. With `E2E_TIER=pr` only chromium and
  mobile-chromium run, and only journeys marked `[critical]` in the inventory.
  On CI the tests run against `docs:serve-static:e2e` (the optimised build with
  source maps, `dist/e2e/docs`); locally against the dev server.
- **Reports**: `reports/e2e/results.json` (Playwright), `reports/e2e/flake-log.json`
  (tests that passed only on retry), `reports/a11y/target-findings.jsonl`
  (target-level axe findings), `coverage/<project>` (unit) and
  `coverage/merged` (unit + e2e, feedback only, no threshold).
- **TSDoc lint**: `eslint-plugin-jsdoc` and `eslint-plugin-tsdoc` rules in
  the root `eslint.config.mjs`.
- **Local registry**: the root project's `local-registry` target (Verdaccio,
  `.verdaccio/config.yml`) was generated by Nx with the publishable library.
  CI and the release flow do not use it.

## Workflows

- `pnpm start` / `nx serve docs`: documentation site dev server.
- `pnpm storybook` / `nx storybook ui`: Storybook dev server.
- `nx run-many -t lint,test,build`: lint (with TSDoc rules), unit tests with
  coverage gate, builds.
- `pnpm test-storybook` / `nx test-storybook ui`: Storybook axe scan.
- `pnpm e2e` / `nx e2e docs-e2e`: Playwright (set `E2E_TIER=pr` for the PR tier).
- `pnpm verify:packaging`: `docs:build:packaging` against `dist/libs/ui`, then
  `npm pack --dry-run` of the package.
- `pnpm e2e:flake-log`, `pnpm e2e:coverage-report`: post-e2e reports.
- CI (`.github/workflows/`):
  - `ci.yml`: pull requests run `verify-affected` and `e2e-affected` (the
    required checks); pushes to `main`/`release` run `verify-all` (lint, test,
    build, packaging gate, Storybook axe scan).
  - `e2e-full.yml`: nightly and on push to `main`; every browser, flake log,
    merged coverage; skips when nothing changed since `refs/e2e/last-full-green`.
  - `e2e-visual-update.yml`: manual, regenerates visual snapshots on a PR branch.
  - `release.yml`: on a `v*` tag on `release`, guards the tag, re-runs CI,
    publishes to npm, then deploys the docs site to GitHub Pages (base href
    `/`, `404.html` copied from `index.html`). Manual runs on `release`
    redeploy the docs only.
- Releases are cut by tagging `v*` on the `release` branch after a pull
  request from `main` into `release`; the version is `libs/ui/package.json`
  and `CHANGELOG.md` must have its heading. See CONTRIBUTING.md.
